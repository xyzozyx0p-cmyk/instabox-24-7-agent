# Архитектура первого этапа

Watchdog запускается на Render Background Worker и/или на третьем постоянном сервере. Он не запускает Claude Code и не считает сам факт ответа API доказательством выполнения задачи.

## Сигналы

`liveness` — состояние машины Instabox через `GET /v1/machines/{id}`. `anti_sleep` — штатный `resume`, если машина находится в paused. `progress` — отдельный файл или API, который обновляет рабочий агент после реального шага задачи. Эти сигналы записываются раздельно.

## Идемпотентность и сбои

Каждый lifecycle-запрос получает уникальный `Idempotency-Key`. При сетевой ошибке watchdog только фиксирует ошибку и повторяет цикл; он не удаляет машину и не считает задачу завершённой. Остановка или restart не включены в первый этап, потому что перед ними нужна согласованная checkpoint-стратегия.

## Состояние

`events.jsonl` предназначен для локального журнала. Для production нужно вынести его и checkpoints во внешнее надёжное хранилище или базу. На бесплатном Render локальная файловая система эфемерна, поэтому нельзя использовать её как источник истины.

## Безопасность

API key задаётся через Render Secret или защищённый EnvironmentFile на третьем сервере. Ключ не должен попадать в Git, логи или сообщения об ошибках. Рекомендуется отдельный ключ с минимальными правами: чтение машин и resume/start только при необходимости.
